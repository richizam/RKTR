# 1. Контекст и цель работ

В рамках проекта анализируется общий CAD-лист производственной линии для railway wheel production. На общем листе присутствуют две основные части: Machining line и Testing line.

Цель работ: на основе полного CAD-листа и уже выделенных частей подготовить две отдельные финальные annotated-схемы, пригодные для дальнейшего использования в UI MES / line traceability.

Схемы должны быть визуально близки к исходному CAD-листу. Требуется не абстрактная инфографика, а упрощенная инженерная схема с сохранением узнаваемой структуры линии, пропорций и расположения оборудования.

# 2. Исходные материалы и визуальные референсы

В качестве основы для ТЗ используются переданные материалы и ранее согласованные вводные:

• общий CAD-лист линии, где в одном листе совмещены Machining line и Testing line;

• ранее выделенные и проанализированные фрагменты: area gantry working layout, linear gantry stroke details, linear gantry working layout, service / maintenance detail views;

• согласованная логика визуализации: выделение мониторируемого оборудования, отображение манипуляторов, их траекторий движения, направления потока детали и traceability по клику на колесо;

• приложенные референсы упрощенных схем, которые задают принцип композиции, рамок, маркировки зон и отображения траекторий.

## 2.1. Роль приложенных изображений

Изображение 1: общий исходный CAD-лист. Используется как главный источник геометрии, взаимного расположения зон и состава линии.

Изображение 2: референс упрощенной схемы Machining line. Используется как ориентир по принципу выделения оборудования в рамки, вынесению названий станций и показу траекторий gantry heads.

Изображение 3: референс упрощенной схемы Testing line. Используется как ориентир по принципу длинной линейной схемы с выделением отдельных станций и показом движения линейных gantry heads.

# 3. Объем работ и состав результата

В финальном комплекте должны быть подготовлены две отдельные схемы:

• Machining line - отдельная упрощенная annotated-схема;

• Testing line - отдельная упрощенная annotated-схема.

На каждой схеме обязательно должны быть отмечены: все станции / единицы оборудования, где показывается текущий статус; все манипуляторы / gantry / shuttle, которые должны анимироваться; траектории их движения; основное направление потока детали. Буферы / накопители показываются обязательно там, где они участвуют в логике линии и в понимании маршрута детали.

Формат выдачи финальной визуализации уточняется отдельно. Базово схема должна быть пригодна для дальнейшей адаптации в UI и для презентационного использования.

# 4. Общие требования к принципу визуализации

• Основа схемы: исходный CAD-лист и его выделенные части. Полная перерисовка линии в виде условной инфографики не допускается.

• Сохраняется CAD-подобный характер изображения: темный фон, инженерная геометрия, тонкие линии, читаемая логика реального расположения оборудования.

• Допускается умеренное упрощение: убрать размеры, строительные линии, второстепенные слои, сервисные детали, монтажные примечания и перегружающие технические подписи.

• Оставляются только те элементы, которые нужны для понимания маршрута детали, статуса оборудования, работы манипуляторов и traceability.

• Станции, буферы и transfer-зоны должны иметь краткие читаемые подписи. Названия должны быть согласованы с функциональной ролью участка, а не с перегруженной CAD-терминологией.

• Поверх базовой CAD-геометрии должны быть добавлены понятные визуальные оверлеи: рамки мониторируемого оборудования, подписи, маркеры статуса, траектории движения, стрелки потока детали и callout для traceability.

## 4.1. Что оставить и что убрать при упрощении

| Оставить | Убрать |
| --- | --- |
| • станки / processing stations | • лишние размеры |
| • измерительные, тестовые и инспекционные станции | • строительные линии |
| • буферы, накопители, conveyor, transfer-зоны | • второстепенные CAD-слои |
| • gantry heads, linear gantry heads, манипуляторы, shuttle | • сервисные детали |
| • основные траектории движения | • монтажные примечания |
| • краткие названия станций | • лишние технические подписи |

# 5. Требования к схеме Machining line

Machining line строится как отдельная схема на основе желтой выделенной зоны общего CAD-листа. Визуально схема должна оставаться узнаваемой относительно исходного блока и в то же время быть достаточно чистой для UI и презентационного использования.

Рекомендуемая логика чтения схемы: слева направо, от infeed / loading к machining stations, затем к buffer, washing, drying, inspection и outfeed.

| Блок / зона | Показывать статус | Показывать манипулятор | Показывать траекторию | Комментарий |
| --- | --- | --- | --- | --- |
| Infeed / Loading | Да | Да, если есть transfer/loading unit | Да | Начальная точка подачи колеса и первый участок контроля логики потока |
| Buffer / Transfer | Да | Да, если задействован shuttle / transfer head | Да | Показать связь между загрузкой и machining-зоной |
| Area Gantry zone | Да | Да | Да | Ключевой анимируемый узел. Обязательно выделить отдельно |
| Machining Station 1 | Да | Через общую gantry system | Да | Показать станцию как объект мониторинга |
| Machining Station 2 | Да | Через общую gantry system | Да | Показать станцию как объект мониторинга |
| Machining Station 3 | Да | Через общую gantry system | Да | Показать станцию как объект мониторинга |
| Intermediate Buffer | Да | Да, если есть buffer shuttle | Да | Показать накопление и передачу детали дальше |
| Washing | Да | Да, если transfer head участвует в перемещении | Да | Показать как отдельный технологический блок |
| Drying | Да | Да, если transfer head участвует в перемещении | Да | Показать как отдельный технологический блок |
| Inspection | Да | Да, если есть inspection manipulator | Да | Здесь особенно важна связь с traceability |
| Outfeed | Да | Да, если есть outfeed manipulator | Да | Финальная точка выхода детали из Machining line |

## 5.1. Обязательные анимируемые объекты на схеме Machining line

• loading manipulator / transfer unit в зоне подачи;

• area gantry в machining-зоне;

• linear gantry heads / shuttle / head, обслуживающие machining stations;

• buffer shuttle при наличии;

• wash / dry transfer head при наличии;

• inspection manipulator при наличии;

• outfeed manipulator при наличии.

# 6. Требования к схеме Testing line

Testing line строится как отдельная схема на основе magenta-выделенной зоны общего CAD-листа и связанных detail views. Схема должна показать последовательность testing-операций, а также все подвижные системы, участвующие в transfer между станциями.

Рекомендуемая логика чтения схемы: слева направо, от transfer from machining и buffer к balancing, measuring, UT, MPT, marking, final inspection и outfeed.

| Блок / зона | Показывать статус | Показывать манипулятор | Показывать траекторию | Комментарий |
| --- | --- | --- | --- | --- |
| Infeed / Transfer from machining | Да | Да, если есть transfer head | Да | Точка входа детали из Machining line |
| Buffer | Да | Да, если используется shuttle | Да | Показать зону ожидания / накопления |
| Loading / Transfer | Да | Да | Да | Показать передачу в testing-зону |
| Balancing | Да | Через общую gantry / transfer system | Да | Отдельный мониторируемый тестовый блок |
| Measuring | Да | Через общую gantry / transfer system | Да | Отдельный мониторируемый тестовый блок |
| UT | Да | Через общую gantry / transfer system | Да | Ultrasonic testing должен быть выделен как отдельная станция |
| MPT | Да | Через общую gantry / transfer system | Да | Magnetic particle testing должен быть выделен как отдельная станция |
| Marking | Да | Да, если задействован marking manipulator / head | Да | Показать отдельную операцию маркировки |
| Final inspection | Да | Да, если есть manipulator или transfer unit | Да | Связать с карточкой traceability |
| Outfeed | Да | Да, если есть outfeed shuttle / manipulator | Да | Финальный выход из Testing line |

## 6.1. Обязательные анимируемые объекты на схеме Testing line

• linear gantry / gantry manipulator;

• transfer head;

• shuttle cart;

• vertical lift, если присутствует в detail views;

• indexing turntable, если присутствует в detail views;

• прочие подвижные transfer-механизмы, видимые в testing layout.

# 7. Правила выделения статуса, манипуляторов и траекторий

## 7.1. Мониторируемое оборудование

• Каждая станция или единица оборудования, для которой в UI должен показываться текущий статус, должна быть выделена отдельной рамкой поверх CAD-основы.

• Рамка должна быть тонкой, контрастной и единообразной по всей схеме. Рекомендуется использовать один цвет для всех monitored equipment frames.

• Рядом с каждой такой рамкой должен быть предусмотрен status marker placeholder. На этапе ТЗ достаточно обозначить место статуса, без детализации финальной логики цветов состояний.

## 7.2. Манипуляторы и движущиеся системы

• Все gantry, shuttle, transfer heads и manipulators, которые должны анимироваться в UI, должны быть показаны как отдельные визуальные сущности.

• Если система обслуживает группу станций, она должна маркироваться как общий motion layer над или под соответствующими станциями.

• Подписи должны быть короткими и функциональными: area gantry, linear gantry head, transfer head, shuttle, inspection manipulator и т.д.

## 7.3. Траектории движения

• Траектории движения манипуляторов показываются dashed lines со стрелками.

• Траектории не должны перегружать схему. Нужно показывать только основные маршруты, которые пользователь должен понять в UI.

• Если движение вертикальное или многокоординатное, допускается схематичное обозначение с поясняющей подписью.

## 7.4. Поток детали

• Основное направление потока детали должно читаться с первого взгляда.

• Поток детали показывается отдельным типом стрелок и не должен смешиваться с траекториями манипуляторов.

• На Machining line и Testing line направление потока задается слева направо, если иное не следует из исходной схемы.

# 8. Требования к traceability и popup по клику на колесо

На обеих схемах необходимо предусмотреть визуальную связь с traceability. По клику на колесо или на объект детали должна открываться карточка с детальной информацией. На схеме достаточно показать callout / popup mockup, который указывает на наличие такого сценария.

| Поле | Требование |
| --- | --- |
| Manufacture code | Обязательно |
| Month / Year / time of stamping | Обязательно |
| Heat code | Обязательно |
| Serial number | Обязательно |
| Operation No | Обязательно |
| Machine ID | Обязательно |
| Operation status OK/NotOK | Обязательно |
| Part type | Обязательно |
| Process parameter 1..20 | Обязательно, допускается свернутое отображение или ссылка View/Open |

# 9. Визуальный стиль и графические ограничения

• Стиль должен быть максимально близок к исходной CAD-схеме: темный фон, инженерные линии, ощущение технического чертежа.

• Схема не должна превращаться в абстрактную инфографику с крупными декоративными иконками и произвольным упрощением геометрии.

• Допустимы только те оверлеи, которые помогают чтению схемы: рамки, стрелки, подписи, траектории, статусы, callout traceability.

• Нельзя выравнивать станции по условной сетке так, чтобы потерялась связь с реальным расположением оборудования на исходном CAD-листе.

• Цветовое кодирование должно быть сдержанным: один цвет для monitored equipment frame, один для trajectories, один для part flow, один для status markers.

• Финальная схема должна быть пригодна для дальнейшей адаптации в UI, поэтому все подписи, рамки и траектории должны быть читаемы на рабочем масштабе.

# 10. Требования к сдаче результата и критерии приемки

Результат считается приемлемым, если обе схемы одновременно выполняют две задачи: сохраняют связь с исходным CAD-листом и позволяют быстро понять структуру линии, monitored equipment, движение манипуляторов и путь детали.

Критерии приемки:

• подготовлены 2 отдельные схемы: Machining line и Testing line;

• на каждой схеме выделены все станции / оборудование, где должен показываться статус;

• на каждой схеме показаны все значимые manipulators / gantry / shuttle;

• для всех анимируемых объектов показаны основные траектории движения;

• на схеме читается основное направление потока детали;

• traceability popup предусмотрен и содержит обязательные поля;

• визуально схема остается близкой к исходному CAD-листу, без ухода в абстрактную инфографику;

• убраны лишние CAD-слои и шум, но сохранена инженерная логика и взаимное расположение зон.

# 11. Комментарий по использованию референсов

Приложенные упрощенные схемы используются как ориентир по композиции и читаемости, но не заменяют структуру исходного wheel line CAD-листа. При разработке финальных схем необходимо брать фактическую геометрию и последовательность оборудования из исходного листа, а принципы рамок, траекторий и общей подачи материала брать из приложенных примеров.
